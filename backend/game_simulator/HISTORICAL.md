# 날짜 제한 및 144경기 전체 검증

날짜를 선택하면 `game_date < as_of`인 기록만 입력합니다. 해당 날짜 경기는 모두 제외하므로
같은 날의 더블헤더 1차전도 2차전 입력에 들어가지 않습니다. 이 모드는 시즌 전체 합계나
브라우저가 보낸 타격 수치로 대체하지 않습니다. 선수 이름/타순만 받아 서버에서 다시 집계합니다.

## 경기별 원본 수집

저장소 루트에서 PowerShell:

```powershell
cd backend
..\venv\Scripts\python.exe -m game_simulator.collect_history --as-of 2026-10-31
```

KBO 공식 선수 일자별 기록을 **정규시즌(시리즈 0)**으로 조회합니다. 기존 CSV에서는 해당
시즌의 선수 ID/이름만 가져옵니다. 연간 성적은 날짜 제한 확률 계산에 사용하지 않습니다.
선수의 경기 당시 팀은 공식 경기 일정의 상대 팀으로 확인합니다. 현재 프로필 소속팀이나
시즌 종료 소속팀으로 과거 기록을 배정하지 않습니다.

로컬 CSV에 없는 시즌 후반 출전 선수가 있을 수 있어 KBO 공식 시즌 참가 명단으로 ID를 보완합니다.
수집 완료 전에 타자/투수의 안타·홈런·볼넷·사구·PA/TBF 합계가 같은지, 선수 득점 합계가
공식 최종 스코어 합계와 같은지 검사합니다. 불일치하면 완료 데이터로 저장하지 않습니다.

- 기본 저장 위치: `backend/data/game_logs/2026.json`
- `SIMULATOR_HISTORY_DIR`로 웹/API 데이터 폴더를 바꿀 수 있습니다.
- HTML·경기 일정·선발 명단 응답은 `raw/`에 캐시합니다. 중단 후 재실행하면 재사용합니다.
- 갱신하려면 `--refresh`를 사용합니다. 수집이 실패하면 완료 파일을 교체하지 않습니다.
- `coverage_before` 이전까지 수집된 자료만 요청할 수 있습니다. 더 늦은 기준일은 다시 수집해야 합니다.
- 수집 데이터는 Git에서 제외됩니다. 다른 실행 환경에서는 수집 명령을 실행하거나 완료 JSON을 복사해야 합니다.
- 선수 ID 목록 자체가 시즌 참가 선수 전체를 포함하는지는 데이터 갱신 시 확인해야 합니다.

## 웹에서 기준일 선택

경기 시뮬레이터의 **기준일 (당일 경기 제외)**을 선택합니다. 선택 시 양 팀의 타자·투수 목록과
기본 타순을 동일한 날짜로 다시 불러옵니다. 기준일 이후 데이터/예시 타순으로 자동 대체하지 않습니다.

- 기본 타순: 기준일 이전 타석 수 상위 9명. 실제 그날 엔트리/선발 타순을 보장하지 않습니다.
- 기본 선발: 기준일 이전 선발 등판 수, 이닝 순으로 첫 번째 선수. 사용자가 변경할 수 있습니다.
- 다른 팀으로 이적한 경우 마지막으로 관측된 **기준일 이전** 소속팀을 사용합니다.
- 해당 시즌 기록이 아직 부족하면 명시적인 오류를 반환합니다. 개막전까지 포함하는 검증은 아래 전체 일정 모드를 사용합니다.
- 날짜 모드 반복 통계는 실제 맞대결 엔진으로 승·패·무와 스코어 빈도를 계산합니다.
- 결과에는 사용 시즌, 기준일, 마지막 반영 경기, 시드, 데이터 SHA256을 남깁니다.

API:

```text
GET /api/simulate/history/LG?as_of=2026-06-01
POST /api/simulate/game   { ..., "as_of": "2026-06-01", "seed": 42 }
POST /api/simulate/multi  { ..., "as_of": "2026-06-01", "seed": 42, "n_games": 10000 }
```

## 실제 720경기, 팀당 144경기 검증

단일 기준일을 고르는 대신 **실제 경기마다 경기 날짜로 기준일을 이동**합니다.

```powershell
..\venv\Scripts\python.exe -m game_simulator.season_backtest --season 2026 --games 10000 --workers 4 --output-dir ..\..\output\simulator-2026-walk-forward
```

1. 공식 정규시즌 일정이 정확히 720경기이고 모든 팀이 144경기인지 확인합니다.
2. 실제 선발 타순·선발투수를 경기 전에 알고 있었다는 조건으로 실행합니다.
3. 해당 경기 날짜 이전 2026년 기록만 집계합니다. 실제 그 경기의 성적이나 결과는 확률 계산에 사용하지 않습니다.
4. 초기 표본과 신인은 2025년 선수 기록 또는 2025년 리그 평균을 30기회 상당의 사전 표본으로 보완합니다.
5. 경기마다 기본 10,000회, 전체 720만 회 반복한 뒤 실제 경기 결과와 비교합니다.

2025년 이후 정규시즌은 최대 11회로 제한합니다. 기존 엔진의 기본 12회 설정을 그대로
사용하지 않습니다. 근거: https://www.koreabaseball.com/MediaNews/Notice/View.aspx?bdSe=11416
고정 라인업의 이벤트 확률을 캐시해 계산을 줄이되 동일한 시드의 스코어 분포가 원래 엔진과
완전히 같은지 검사했습니다.

타자 사전 표본은 기존 엔진의 분모인 `AB+BB+HBP`, 투수는 `TBF` 기준입니다.
혼합 확률은 `(당해 시즌 사건 수 + 이전 시즌 확률 × 30)/(당해 시즌 기회 수 + 30)`입니다.
30은 사전에 고정한 기본값이며 2026년 결과를 보고 최적화한 값이 아닙니다.
2025년 CSV에서 2026년 행은 읽지 않습니다. 시즌 중 이적 선수의 과거 기록은 선수 ID로 합산합니다.

공식 박스스코어의 이름은 동명이인이 있을 수 있습니다. 실제 선발 명단의 ID를 복원할 때
당일 일자별 행을 박스스코어와 대조할 수 있으나, 이 과정의 수치는 확률 계산으로 전달하지 않습니다.
예측 입력 함수에는 확인된 선발 선수 ID와 **기준일 이전** 기록만 전달합니다. 구분하지 못하면 중단합니다.

출력:

- `config.json`: 데이터 지문, 시즌, 반복 횟수, 시드, 사전 표본 정책.
- `games.jsonl`: 경기별 실제 결과, 승리 확률, 평균 득점, 실제 스코어 빈도, 기준일, 선수별 사용 표본/확률.
- `summary.json`, `report.md`: 적중률(실제 무승부 제외), Brier 점수, 시즌 예상 승수 오차, 득점 비교.

## 해석상의 범위

이는 실제 일정에서 경기 전에 알려진 기록으로 각 경기를 평가하는 사후 검증입니다.
앞선 실제 경기의 성적을 다음 날짜 입력에 반영합니다. **개막 전에 시즌 전체를 한 번에 예측하는 실험과는 다릅니다.**
모든 경기에서 고정 9명과 선발 보정을 사용하며, 불펜·대타·수비 교체·구장·날씨는 모형에 추가하지 않았습니다.
일자별 투수 기록은 2·3루타를 분리하지 않으므로 비홈런 안타를 단타 80%/2루타 20%로 나눕니다.
공식 사이트에서 현재 정정된 과거 기록을 가져오므로 당시 공개 기록의 정정 전 버전을 복원하는 것은 아닙니다.

검증:

```powershell
..\venv\Scripts\python.exe -m unittest tests.test_historical_simulator tests.test_match_simulator tests.test_score_plots -v
```

기준일 당일/이후 기록과 이후 이적 팀을 바꾸어도 입력이 변하지 않는지, 개막전의 이전 시즌 보완,
클라이언트 수치 변조 무시, 중복·불완전 기록 거부, 시드 재현성, 승패 합계 등을 검사합니다.
